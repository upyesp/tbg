# Passkey-only identity via Cognito with no custom server compute

All identity is passkey-only (WebAuthn): no email, username, or password is ever collected, for maximum privacy. Sign-in uses an Amazon Cognito user pool (Essentials tier, passkeys as first factor, eu-west-2; free to 10k MAU), and a Cognito Identity Pool issues temporary scoped IAM credentials so the browser talks directly to DynamoDB — no Lambda, no AppSync, zero custom server code. Considered and rejected: a self-hosted Lambda API (it is exactly the "cloud processing" the project avoids) and local-only operation (cloud sync is core to the product). Consequences: account recovery relies on multiple passkeys plus a one-time Recovery Code; the first run requires connectivity. Verified viable 2026-09 (see docs/research/location-apis-and-passkey-auth.md).
